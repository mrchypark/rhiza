# Rhiza 0.18.0

## Changes

- Upgrade LatticeDB Go from v0.9.0 to v0.10.0, using its transactional
  page-backed storage engine (bbolt v1.5.0).
- Retry graph writes blocked by pinned snapshots instead of recording temporary
  mmap-growth and snapshot-write limits as durable command rejections.
- Propagate QUIC request cancellation to stream I/O and checkpoint preparation
  without discarding the shared connection.
- Return `ErrCommitUnknown` with the request ID when a notification is canceled
  after submission, so callers can reconcile an uncertain outcome safely.

## Compatibility and installation

LatticeDB v0.10.0 migrates legacy graph checkpoint/WAL storage to its page-backed
format when opened. Older LatticeDB versions cannot directly open that format.
Keep pre-upgrade backups and the retained legacy source files for rollback;
verify restoration before upgrading production data. Publishing this release
performs no production migration. Existing Rhiza consensus identity and recovery
requirements still apply.

Use `go get github.com/mrchypark/rhiza@v0.18.0` or `rhizadb = "0.18.0"`.
Source builds require Go 1.27+ and, for Rust, a C compiler. Match native archive
and Rust crate versions when using `RHIZA_NATIVE_LIB_DIR`.

## Verification

Regression tests cover QUIC stream cancellation and connection reuse, uncertain
notification outcomes, and retrying real page-store writes after snapshots close.
The release candidate must pass repository CI before publication, including
external-module consumption, Rust packaging, and recovery qualification.
