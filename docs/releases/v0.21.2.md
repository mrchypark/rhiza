# Rhiza 0.21.2

## Local maintenance release acknowledgements

A Local archive holder now reconciles an errored conditional maintenance
release through bounded, stable readback. It accepts release completion only
when the exact expected free control is observed at a changed object version.
This avoids treating an already completed release as failed solely because its
acknowledgement was lost or delayed. The release upload timeout is unchanged.

Unknown work, an unresolved held control and unreadable state remain
fail-closed. Work errors and cancellation are preserved. This is not an
automatic takeover API for an orphaned remote maintenance token.

No archive format, identity, receipt or public API changes are required.
Existing archives with free control may use the normal same-identity Open path,
subject to all ordinary binding, history, replay and data checks. Free control
or TCP readiness alone does not establish recovery success.

Regression coverage includes committed and uncommitted release failures,
delayed acknowledgements, cancellation, uncertain work and payload preservation.
The same provider fixture exercises S3, GCS and Azure adapters against pinned
emulators. Qualification results must be checked for the release commit;
this source document does not assert a completed release or live-cloud test.

The BeforeAck checkpoint-and-tail test also separates its live archive
observation from unrelated periodic sync, without relaxing durability checks
or retrying an unstable observation.
