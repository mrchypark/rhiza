# Rhiza 0.17.0

## Changes

- Add explicit local embedded mode: Go `Config{Local: true}` and Rust
  `Config::local()`. No peer transport or listener is created; operator listeners
  and conflicting network, membership and object-store configuration are rejected.
- Retain the existing single-node consensus, certified WAL, SQL/KV/graph engines,
  receipts and restart recovery. Default networked behavior is unchanged.
- Local mode provides no replication or remote backup. The existing local WAL
  size limit applies. Hosts may still deliberately serve exported Go handlers.

## Compatibility and installation

This release does not change the 0.16.0 storage format. Existing registered voter
identities and non-singleton histories cannot be opened as local databases.
The 0.15.x fresh-cluster/logical-import requirement still applies; see
[the migration guide](../sql-execution-policy.md). Publishing performs no production
migration.

Use `go get github.com/mrchypark/rhiza@v0.17.0` or `rhizadb = "0.17.0"`.
The Rust crate is a library, not a `cargo install` executable. Source builds need
Rust, Go 1.27+ and a C compiler. Matching stripped native archives can be selected
with `RHIZA_NATIVE_LIB_DIR`; never mix archive and crate versions.

## Qualification

PR #172 passed all 12 CI checks, including Go, Rust on Linux/macOS, containers,
membership, operator chaos and paired benchmarks. Independent Pro implementation
and full-PR reviews reported no actionable findings. Local functional checks
covered SQL/KV/graph, receipts, derived-state replay, undecided recorder recovery,
mode transitions and rejected voter identities; a live process had no TCP/UDP
descriptors. These checks do not establish power-loss safety or a local-mode speedup.
