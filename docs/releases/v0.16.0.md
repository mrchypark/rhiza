# Rhiza 0.16.0

This is a compatibility-breaking release. Existing 0.15.x installations need a
fresh cluster and logical application-data import; do not upgrade their physical
data directories, checkpoints, or certified history in place. Follow
[the migration guide](../sql-execution-policy.md), retaining the old binary and
evidence until outstanding outcomes are reconciled. No production migration is
performed by publishing this release.

## Changes

- Replicated SQL uses policy 4: deterministic connection counters and receipts,
  cancellation cleanup, and guards for TEMP objects, exhausted ROWIDs, persistent
  virtual tables and node-local PRAGMA evaluation.
- WAL framing protects its length with a header checksum; incomplete appends and
  incompatible history fail safely. Previous WAL formats are not replayable.
- Object-store recovery and garbage collection verify exact write payloads and
  current lease/ownership evidence.
- Reconfiguration preserves generation-relative leader schedule slots across
  freeze, drain and abort; checkpoint restart retains the required leader orders.
  Incompatible certified schedule history is rejected without rewriting it.
- The graph engine dependency is `github.com/mrchypark/latticedb-go v0.9.0`.
  Graph migration also requires logical import, not old decision replay.
- Peer protocol is `rhiza-peer-v7`, without older-protocol fallback. Mixed-version
  clusters and downgrades are unsupported; ALPN does not prevent an old binary
  from opening a WAL by itself.

## Installation

Use `rhizadb = "0.16.0"` in Cargo dependencies. This is a library, not a
`cargo install` executable. The crate includes its Go source dependency closure;
source builds require Rust, Go 1.27+ and a C compiler on supported macOS/Linux GNU
platforms. Alternatively select the matching release's stripped native archive
with `RHIZA_NATIVE_LIB_DIR`, as documented in the Rust SDK README. Do not combine
an archive from another version with this crate.

Published tags, crates.io versions and native archives must match. Qualification
results and attached native targets are recorded on the GitHub release. Version
0.15.2's historical known-issue notice remains in the SDK README.
