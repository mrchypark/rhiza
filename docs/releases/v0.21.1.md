# Rhiza 0.21.1

## Changes

This documentation-only release clarifies existing Local object-storage backup
and recovery behavior. It makes no runtime, archive-format, or API changes.

Local object-store backups stream while the database is open. An init process
may open the existing Go SDK with the intended Local configuration to restore an
empty `DataDir`, then close it successfully before the main process opens the
same `DataDir` with the same storage identity. The init and main processes must
not overlap: the deployment must establish that the prior owner has stopped.
The open/close sequence is not a new staging API or a replacement for fencing.
See the [init-container guide](../local-init-container-recovery.md) and the
[Local backup and recovery contract](../embedded-object-storage.md).

## Compatibility and installation

The [v0.21.0 archive-format and filesystem ownership warnings](v0.21.0.md)
still apply. This release adds no archive compatibility guarantee and performs
no production migration. Preserve existing evidence when recovery fails; do not
delete or replace an archive to bypass a refusal. Async durability retains its
loss window, and the Local procedure is not an HA qualification.
