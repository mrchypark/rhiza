# Rhiza 0.21.0

## Changes

- Recover acknowledged Local filesystem archives after process termination by
  acquiring process-lifetime ownership and validating the archive before
  releasing a retained maintenance gate.
- Keep uncertain filesystem work fail-closed while the owning process remains
  alive; remote object stores continue to use conditional writes and do not gain
  filesystem-owner crash recovery.

## Compatibility and installation

This release changes the fixed Local archive format for every Local archive,
including filesystem, S3, GCS, and Azure archives. It does not migrate, adopt,
or delete older or partial archives; they are rejected without modification.
Preserve existing archive data and confirm compatibility before upgrading any
deployment that uses Local archives. A greenfield deployment requires a fresh
`DataDir` and fresh archive; do not treat a rejected archive as permission to
initialize a replacement namespace. No existing data is deleted or migrated.
Do not run an older unfenced client concurrently against a Local filesystem
archive.

The filesystem ownership guarantee applies to `rhiza.Open` with Local and the
filesystem provider on supported Linux and macOS local filesystems. Configure a
dedicated, trusted, stable archive root disjoint from `DataDir`; the root and
its parent must not be renamed, replaced, remounted, or externally removed
while the process is using them. The advisory lock coordinates cooperating
processes and does not fence external path changes or power loss. Explicit
`Async` durability retains its existing loss window; use `BeforeAck` when a
successful mutation response must be present in the archive.

S3, GCS, and Azure do not use the filesystem owner. Unknown or held remote
maintenance state remains fail-closed and is not cleared by age or process
absence.

Publishing this release performs no production migration. Keep a verified
backup and validate the target deployment's archive before upgrading.

## Verification

The release candidate must pass repository CI and release-specific packaging
checks before publication. Local process-crash and unit tests do not establish
power-loss, external filesystem mutation, or real-cloud qualification.
