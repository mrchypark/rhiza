# Rhiza 0.22.2

This patch preserves the existing Go and Rust SQL APIs. Managed KV development
is not included.

## Fixes and maintenance

- Preserve SQLite cancellation/deadline causes through query preparation and
  network query errors, without changing write retry or commit-unknown policy.
- Wait for in-flight background checkpoint work before closing or adopting its
  materializer files. The regression covers the actual SQLite driver lifetime.
- Preserve commit-unknown after successful SQL/KV submission when a subsequent
  receipt lookup fails or the receipt is missing. A missing receipt does not
  authorize resubmission.
- Keep fixture-owned UDP sockets reserved across managed startup, replacement
  and restart. CI explicitly executes the two S3 FFI three-node/lifetime tests
  against an isolated pinned Floci endpoint and verifies their cleanup.
- Reduce SQL batch encoding allocations for blob parameters. This focused codec
  improvement is not a claim of better overall server throughput or latency.

## Operator images and packaging

The operator release workflow supports native `linux/amd64` and `linux/arm64`
builds and checks all three binaries as a non-root user. Release publication
preserves BuildKit provenance; the final runnable manifests and version/latest
digests must be verified after publication. Native SDK archives remain separate
four-platform artifacts.

Use the v0.22.2 native archive with the v0.22.2 Rust crate; do not mix versions.
The source-crate workflow verifies exact staged source, bundled native code and
extracted-package tests. Publication requires the final merged source artifact
and byte-identical metadata-only repackaging.

## Evidence and remaining limitations

Local Rust-to-FFI S3 recovery qualification at source `4958acf` covered preserved
quorum, Pod replacement, same-Pod restart and acknowledged data. It does not prove
this patch's full source on real GCS, network partition, physical node failure
or whole-quorum recovery. Emulator SDK contracts are not production-cloud parity.
The existing provider-only Kubernetes and filesystem-path fixtures are skipped
where inapplicable, not counted as passes.

No new managed KV Host/Rust API or mixed-policy runtime qualification is claimed.
Custom managed recovery checkers still need the required recovery-checker
contract; unsupported or unconfirmed recovery continues to fail closed.
